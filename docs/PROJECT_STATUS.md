# 현재 목표와 작업 재개 안내

마지막 정리: 2026-10-02

## 업무 목표

현장 사진 여러 장을 Photoshop에서 접합해 만든 성벽 사진 위에 사람이 돌을 트레이싱합니다.
사진마다 약 3~9시간 걸리고, 회사에는 이를 수행하는 측량사가 약 3명이며 월 5건 이상,
성수기에는 15건 이상이 있습니다. 이번 목표는 **닫힌 돌 윤곽을 자동 작성하고 사람이 빠르게 고쳐
트레이싱 시간을 줄이는 것**입니다. 전체 CAD 도면, 표고, 문자, 치수는 자동 출력 대상이 아닙니다.

지금은 개발자가 Mac·Windows에서 실험할 로컬 도구를 만듭니다. 측량사 전용 상용 앱을 완성하는 단계가 아닙니다.

## 알고 있는 기존 파이프라인

```text
Photoshop 접합 사진
 → SAM이 범용 영역 마스크 후보 생성
 → CV가 마스크 외곽을 단순한 점 목록으로 벡터화
 → 닫힌 폴리라인을 DXF로 출력
 → 사람이 CAD에서 후보를 고치고 빠진 돌 추가
```

초기 MVP에서 실행되는 경로는 OpenCV 이미지 읽기 → SAM 자동 마스크 생성 → 후보 품질·면적
필터링과 중복 억제 → `findContours` / TC89 윤곽 근사 → y축 반전 → ezdxf 출력입니다.
현재 좌표계·마스크 후처리·실측 위치 지정은 서로 다른 단계입니다.

오래된 PyQt6 화면은 전체 이미지를 1024픽셀 안으로 축소해 추론합니다. 화면의 `approxPolyDP`
표시만 있고, 기존 DXF 내보내기와 실행 취소는 연결되지 않았습니다. `MaskProcessor`의
평활화·단순화 기능도 주 화면의 내보내기 흐름에 연결되지 않았습니다. 현재 개발 진입점은
이전 화면 대신 저장된 돌 좌표를 수정하는 별도 `contour_editor`입니다.

2026-10-01 SAM 1 ViT-B 타일 실행은 마스크 후보를 만들고 CV로 실루엣을 정리해
8개 타일에서 닫힌 윤곽 319개를 출력했습니다. CPU 추론 누적 시간은 약 303초였습니다.
이 파이프라인은 첫 검토용 단일 가로 사진에 맞춘 프로토타입입니다. 다른 사진에서 성능을
확인했거나 반복 작업에 쓸 제품 코어로 정리한 상태는 아닙니다. 세부 수치는 이 폴더의
`baselines/building_001_v1/plan.json`, `summary.json`에 있습니다.

## 제도 기준과 한계

- 돌 **정면 실루엣**을 그립니다. 옆·뒤로 깊이 들어간 면을 앞면에 포함해 뾰족한 돌출을 만들지 않습니다.
- 윤곽은 지나치게 자잘하게 묘사하지 않습니다. 적절한 단순화 정도는 사진별로 검토가 필요합니다.
- 식생이나 이끼에 가린 선은 사람이 주변 모양에 맞게 추정할 수 있습니다. 영상에서 실제 보인 경계와 사람의 추정을 구분해야 합니다.
- 형태를 추정하기 어려운 매몰 경계는 열린 선도 허용하지만, 닫을 수 있는 돌부터 자동 처리해도 업무에 도움이 됩니다.
- 현재 DXF는 원본 사진 픽셀 좌표와 단위 없음입니다. 사람 작성 `building_001_target.dxf`와 사진의 배치점·축척은 확인되지 않았으므로 둘의 겹침을 정확도 점수로 해석하지 않습니다.
- 제공한 한 장의 전체 초안은 사용자가 정성적으로 합격이라고 평가했습니다. 319개 전부의 개별 승인, 시간 절감 실측, 다른 현장 검증을 뜻하지 않습니다.
- 주요 알려진 오류는 사진 접합부·식생 가림이며, 일부 뾰족한 정점은 로컬 편집으로 고칠 수 있습니다.

## 기준본과 사용자 선택

`baselines/building_001_v1/candidates.json`은 합격 당시 319개 입력 좌표의 읽기 전용 기준본입니다.
원본 사진 SHA256은 `5fdcb61b…04b8c6a`, 기준본 JSON SHA256은 `050231a2…17bd741`입니다.
전체 해시와 설정은 보존된 JSON에 있습니다. 입력 JPEG, 사람 작성 DXF와 진행 중인 편집 프로젝트는 `../inputoutput/`에 둡니다.

첫 20개 돌의 강도 선호는 B 3개, C 9개, 셋 다 수정 필요 8개입니다. 21~24번 응답은 없습니다.
이는 선호 샘플 선택이지 전체 현장 정답 라벨이 아닙니다. 원본 응답 표는
`decisions/stone_preferences.json`에 보존했습니다. 정면 경계에 관한 돌 03·05·07의 사용자 피드백은
`decisions/front_face_feedback.json`에 보존했습니다.

## 현재 소프트웨어와 실행

메인 진입점 `contour_editor`는 사진과 저장 윤곽을 열고 정점 이동·추가·삭제, 돌 삭제,
Undo/Redo, 편집 프로젝트 재열기, DXF 출력을 지원합니다. 좌표 편집 시 인접한 돌 좌표를
바꾸지 않습니다. 현재 편집 위치의 작은 면적 겹침도 표시하며, 겹침은 자동 삭제·절단하지 않습니다.

편집기 설치·실행·조작은 [16_minimal_editor.md](16_minimal_editor.md)에 있습니다.
겹침 판정의 보정 내용은 [17_overlap_display_fix.md](17_overlap_display_fix.md)에 있습니다.

개발 브랜치 `codex/minimal-contour-editor`에 작업을 커밋합니다. Git 밖의 두 원본 자료는 그대로 유지하고,
사진 자체나 고객 현장 이미지가 든 압축 묶음은 저장소에 복사하지 않습니다.

## 다음 작업 순서

1. 편집기를 기준본 사진과 좌표로 엽니다. 10개 정도의 인접 돌을 골라 윤곽을 고칩니다.
2. 고친 프로젝트와 DXF를 저장해 AutoCAD에서 사진 위에 배치하고 필요한 윤곽을 추가합니다.
3. 처음부터 트레이싱한 결과와 비교할 때 사진 준비·수정·삭제·누락 돌 추가·최종 검수 시간을 함께 기록합니다.
4. 이 편집 흐름이 유용하면, 타일 실행 스크립트를 이미지·모델·출력 경로를 받는 재사용 코어로 정리합니다.
5. 서로 다른 3~5개 현장에서 입력 좌표·윤곽 품질·사람이 고친 범위와 시간을 기록한 뒤 AI 전처리 또는 학습 필요성을 판단합니다.

사진 접합부·식생을 이미지 모델로 고치는 방법은 이후 후보입니다. 원본 보존, 처리 영역 지정,
사람 수정과 모델 수정의 분리 비교부터 설계합니다. 유료 API나 원본 외부 업로드는 아직 선택하지 않았습니다.
